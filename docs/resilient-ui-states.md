# Northstar 页面状态与故障恢复验收手册

> 对应第一阶段第七步。目标不是模拟 Supabase 管理后台多久刷新，而是验证浏览器发出的请求在成功、变慢或失败时，页面始终给出准确状态，并且不会悄悄丢失或重复用户操作。

## 1. 已实现状态契约

| 场景 | 页面必须表现 | 数据必须表现 |
|---|---|---|
| 首次读取中 | 只显示 `Loading your workspace…`；不闪现示例数据或错误空白页 | 不执行重复初始化 |
| 读取失败 | 显示可理解的错误和 `Try again` | 不以默认数据覆盖云端数据 |
| 保存中 | 顶部显示 `Saving`；当前表单、拖拽和其他写操作暂时禁用 | 同一时刻只允许一个写请求 |
| 保存失败 | 保留弹窗和已填内容，显示错误横幅 | 页面不伪装成功；本地状态保持上次服务器确认值 |
| 空工作区 | 显示明确空状态和恢复示例按钮 | 恢复仍调用原子化重置 RPC |
| 会话失效 | 清除本地会话并返回登录页，显示过期说明 | 不再继续访问业务表 |
| 退出失败 | 留在当前页面并提示重试 | 不假装已经退出 |

数据库 Table Editor 可能延迟显示约 90 秒，这不作为前端失败判据。保存是否成功先以页面成功提示和刷新后数据是否仍存在为准；需要核对数据库时，再等待后台刷新或重新打开表格。

## 2. 测试准备

1. 运行 `npm run dev`，打开终端给出的本地网址并完成邮箱验证码登录。
2. 浏览器按 `F12` 打开开发者工具，选择 **Network（网络）**。
3. 先确认正常网络下 `/app` 能看到当前用户自己的项目。
4. 故障测试只使用一条名称唯一的临时任务，例如 `UI state test 2026-09-07`；结束后删除它。

推荐在测试账号执行。断网模拟只影响当前浏览器标签，不会修改 Supabase 配置。

## 3. 必测用例与理想结果

### A. 首次加载不会闪错数据

1. 在 Network 面板把速度设为 **Slow 3G**。
2. 刷新 `/app`。
3. 等待工作台出现，再把速度恢复为 **No throttling**。

理想结果：等待期间只出现 `Loading your workspace…` 和转圈图标；不会先闪现 7 条默认任务，也不会出现可操作的空看板；加载完成后一次性显示该账号的真实数据。

### B. 加载失败可以恢复

1. 在 Network 面板勾选 **Offline**。
2. 刷新 `/app`。
3. 取消 Offline，点击 `Try again`。

理想结果：断网后停止转圈并显示 `We couldn’t load your workspace.`、连接提示和 `Try again`；不会无限加载。恢复网络后点击一次即可进入工作台，云端原数据没有变化。

### C. 保存中可见且防重复

1. 设置 **Slow 3G**，点击 `Add task`，填写唯一任务名并提交。
2. 请求未完成时观察顶部和弹窗，并尝试再次提交、按 Esc、点击遮罩、拖动旧任务。
3. 请求完成后恢复正常网速。

理想结果：顶部显示 `Saving`，提交按钮显示 `Saving…`；表单和所有写操作禁用，弹窗不能被意外关闭；成功后弹窗关闭且只出现一条新任务。刷新页面后仍恰好一条同名任务。

### D. 新建或编辑失败不丢表单

1. 打开新建任务弹窗，填写标题、截止日期和备注；提交前切为 **Offline**。
2. 点击提交，等错误出现。
3. 恢复网络，在仍打开的弹窗中再次提交。

理想结果：失败时弹窗不关闭，全部输入内容仍在；顶部出现 `Could not add this task. Check your connection and try again.`；页面不新增假任务。恢复后再次提交只创建一条，刷新后仍存在。

编辑已有任务也应相同：离线保存失败后卡片保持旧的服务器确认值，弹窗保留新输入；恢复网络重试后才更新。

### E. 拖拽失败不制造假状态

1. 记住一条任务当前列，切为 **Offline**。
2. 把它拖到另一列，等待失败提示，再刷新页面。

理想结果：显示 `Could not move this task...`；卡片留在原列，列计数和进度不发生假变化；恢复网络并刷新后仍在原列。正常网络重新拖动后才进入目标列。

### F. 删除和重置失败可安全重试

1. 打开一条临时任务的编辑弹窗，切为 Offline 后点击删除。
2. 对 `Reset workspace` 另做一次相同测试；不要在包含重要数据的账号进行成功重置。

理想结果：两种失败都显示错误，确认弹窗保持打开且暂时禁用；请求结束后可以恢复网络重试。失败时任务、里程碑和统计均不变，不会留下半套示例数据。

### G. 空工作区有明确出口

此项仅用无重要数据的测试账号。在 Supabase Table Editor 中先记录该账号项目 ID，再删除该项目下全部 `tasks`，然后删除全部 `milestones`，最后刷新 `/app`。

理想结果：项目概览仍存在，下方显示 `Your workspace is empty.` 和 `Restore example workspace`，不显示损坏的空看板。点击恢复后得到同一项目 ID、3 个里程碑、7 个任务和 14% 进度；刷新后保持。

### H. 会话失效与退出

1. 正常点击右上角退出。
2. 验证过期说明的页面分支：直接访问 `/login?reason=session-expired`。
3. 登录后在另一个同账号窗口退出，再回到原窗口尝试一次保存或刷新。

理想结果：正常退出回 `/login`，再访问 `/app` 仍被拦截；带 `reason=session-expired` 时显示 `Your session expired. Log in again to continue.`；原窗口检测到会话丢失后回登录页，不会继续显示可写的工作台。

### I. 快速回归

正常网络下各执行一次：搜索、里程碑筛选、新建/编辑/删除任务、新建/编辑/删除无任务里程碑、拖拽、退出再登录。

理想结果：行为与第六步一致；每次成功写入都有成功提示，刷新后保持；页面没有无限加载、重复行或阻断操作的残留 `Saving`。

## 4. 第七步通过标准

- [ ] A：慢速首次加载不闪现错误工作区。
- [ ] B：读取失败可见、可重试、无数据覆盖。
- [ ] C：保存中提示清楚且无法重复提交。
- [ ] D：写入失败保留表单和上次确认数据。
- [ ] E：拖拽失败不改变卡片真实状态。
- [ ] F：删除/重置失败不产生部分数据。
- [ ] G：空工作区可恢复为同项目下的 3 个里程碑和 7 个任务。
- [ ] H：退出和会话失效都回登录页。
- [ ] I：正常网络核心功能回归通过。
