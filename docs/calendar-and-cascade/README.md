# 周日历与里程碑级联删除

## 部署顺序（必须先更新数据库）

1. Supabase → SQL Editor → New query，完整粘贴 `supabase/migrations/20261024090000_calendar_and_milestone_cascade.sql`，运行一次。
2. 理想结果：`Success. No rows returned`。迁移在事务内修改任务外键为 `ON DELETE CASCADE`，创建 `calendar_events` 表、索引、更新时间触发器、四条 RLS 策略。已有任务不变；新删除操作才触发级联。
3. 至少有两个已有 Auth 用户后，新建查询，完整粘贴 `supabase/tests/005_calendar_and_cascade.sql` 并运行。
4. 理想结果：`PASS: calendar isolation, duration and milestone cascade`。测试临时创建的记录会回滚，不删除现有业务数据；失败后如编辑器仍在事务中，先运行 `ROLLBACK;`。
5. 本地运行 `node --test tests/calendar.test.mjs`、`npm run check:release`，再部署前端。

未执行迁移时，有任务的里程碑删除仍会被旧数据库拒绝；日历显示 setup pending 提示，不能保存。前端不会把这些情况显示为成功。

## 功能与边界

| 部分 | 行为 |
|---|---|
| `/app` | 原规划页；里程碑编辑弹窗可以删除任意里程碑，包括最后一个 |
| `/app/calendar` | 受认证守卫保护的周日历；导航抽屉在两页间切换 |
| 删除 | 明确展示关联任务数，二次确认后单次删除里程碑，由数据库原子级联；成功后同步清理本地卡片和筛选 |
| 全部删除 | 保留项目；禁止创建无里程碑任务，允许新增首个里程碑或恢复示例 |
| 日历 | 全宽铺满顶栏以下视口；周一至周日，06:00–24:00 共 36 个半小时格，顶部从 06:00 显示；三段低饱和底色，无时段文字图例 |
| 顶栏 | Northstar 后为可编辑个人座右铭；月份、上一周/Today/下一周也收进同一导航栏 |
| 座右铭 | Supabase Auth `user_metadata.northstar_motto`：每个用户唯一字段，修改覆盖；最多 160 字符，可清空；不需要新 migration |
| 事项 | 标题、日期、开始和结束；点击空格新增，点击色块编辑/删除；重叠事项并排展示 |
| 时间 | 按设备本地时区展示，转换为 UTC `timestamptz` 保存；结束必须晚于开始，允许 23:30–24:00；本版不支持手动创建跨日事项 |
| 数据 | 日程独立于里程碑任务，不参与项目完成率；重置规划不会删除日程 |
| 安全 | `owner_id` 默认 `auth.uid()`，数据库 RLS 验证四类操作；匿名无权限，不能变更所有者越权 |
| 故障 | 失败保留表单；保存中禁用重复提交和抽屉切换；周请求序号避免快速翻周产生旧响应覆盖 |

## 人工验收

使用无重要内容的测试账号进行真实删除；确认后无法从页面撤销。

| 测试 | 操作 | 理想结果 |
|---|---|---|
| 关联删除 | 建一个临时里程碑，添加两条任务，编辑里程碑 → Delete → 确认 | 提示删除 2 条任务；里程碑、两条卡片消失，统计更新，刷新不恢复；其他里程碑任务不受影响 |
| 取消删除 | 点击 Delete 后 Keep milestone | 不发出删除操作，数据不变 |
| 最后一个 | 测试账号删完所有里程碑 | 空工作区可添加首个里程碑；Add task 禁用；项目仍在且刷新不自动恢复示例 |
| 导航 | ☰ → Weekly calendar → Project planner | 正确切换 `/app/calendar`、`/app`；直接刷新日历 URL 正常（部署须已配置 SPA fallback） |
| 半小时新增 | 本周某日 09:30 格点击，填事项，结束选 11:00，保存 | 色块出现在该日 09:30–11:00，高度为三个半小时格，刷新仍在 |
| 非法时间 | 开始 10:00、结束 09:30 或相同时间 | 弹窗内报错、不请求保存、不关闭；改正后可成功 |
| 午夜 | 点击 23:30，结束 24:00 | 占据最后一格，不在次日 00:00 重复出现 |
| 编辑与删除 | 色块 → 修改标题/时间/日期 → 保存，再点击删除并确认 | 色块移动到正确位置，数据库同步，刷新不恢复旧值 |
| 周切换 | 前一周/下一周快速点击，Today 返回本周 | 只显示目标周事项，无上一周旧响应污染；跨月、跨年正确 |
| 重叠 | 同日新增 09:00–10:00 与 09:30–10:30 | 色块并排均可点击，不互相完全遮盖 |
| 离线 | 打开事项弹窗、断网后保存，再恢复网络重试 | 提示失败、保留输入、不制造假色块；重试成功且只有一条 |
| 两账号 | A 新增事项，另一浏览器登录 B | B 看不到 A 的事项；同账号另一浏览器刷新可读到 |
| 会话 | 退出后直接访问 `/app/calendar` | 跳到登录；正确登录后返回日历；会话错误时提示重新登录 |
| 手机 | 视口宽度 390px | 顶栏分两行；七天仍同屏，时间格区域可纵向滚动，页面无横向溢出；表单按钮完整可见 |

## 全宽布局与座右铭验收

1. 登录 `/app/calendar`：导航栏下直接是日期表头和周时间格，没有独立大标题、说明区、圆角看板或外侧留白；首行 06:00、末格 23:30–24:00。
2. 在 06:00–12:00、12:00–18:00、18:00–24:00 检查底色与色块，颜色随时间区间变化；不显示任何时段文字图例。12:00 与 18:00 的边界准确对齐。
3. Northstar 后点击 `Add your motto` 或现有座右铭，输入中文或英文保存：顶栏立即更新，刷新后保留；另一浏览器登录同账号也能读到。
4. 再次编辑并保存：替换原座右铭，不创建多条记录；清空保存后显示 `Add your motto`。
5. 断网后保存：保留输入并显示错误，不覆盖上次成功值；恢复网络可重试。取消编辑不保存。
6. 用户 A/B 使用不同座右铭，退出并换账号后互不串用。长座右铭在顶栏省略展示，点击编辑可看到完整内容，不挤坏日历导航。
7. 06:00 以前的旧日程没有删除：只是不在当前可见时间范围内；跨过 06:00 的日程从表格顶部显示其可见部分，编辑仍保留真实开始时间。

座右铭使用 `auth.getUser()` 读取最新用户资料、`auth.updateUser()` 更新单一元数据字段；不承担任何权限判断。不要将 user metadata 当作 RLS 或管理员角色依据。

自动检查：`node --test tests/*.test.mjs` 与 `npm run check:release`。开发服务器中的 `/tests/fixtures/calendar-ui.html` 是独立内存数据的界面验收页，复用真实组件但不写 Supabase；加 `?failSave=1` 可验证座右铭首次保存失败后的重试，加 `?longMotto=1` 可检查长文本布局。该页面不是生产路由，不参与正式构建入口。

## 模块职责

- `NavigationDrawer.vue`：视图导航、Esc 关闭、焦点约束与返回。
- `WeeklyCalendar.vue`：周浏览、编辑表单、异步状态、当前时间线。
- `domain/calendar.js`：本地周日期、UTC 转换与重叠布局，可脱离 Vue 测试。
- `calendarRepository.js`：唯一的日程数据库接口，不在组件中直接调用 Supabase。
- 迁移不包含任何密钥；客户端仍只使用 publishable key。

回滚前端到旧版本仍兼容新表，但新级联删除语义继续生效。撤销数据库迁移不会恢复已删除数据，因此不要为了回滚页面去删除日程表。
